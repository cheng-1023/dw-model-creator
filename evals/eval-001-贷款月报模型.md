# eval-001：贷款月报模型设计（含混合粒度）

## 触发场景

用户提出模型设计需求：

> "帮我设计一张贷款月度模型表：既要按月份×机构×产品看产品月末贷款余额，
> 也要按月份×机构看机构月末贷款余额。"

## 输入要点

- 实体类型：`physical-model`（目标层由 Skill 推断为 DM，用户未显式指定时按需求粒度判断）
- 隐含指标口径：月末贷款余额（若术语库未登记口径，应派生 metric 实体或人工确认）

## 预期行为

1. **拆分粒度**：识别出两个独立原生粒度——`月份×机构×产品` 与 `月份×机构`；建立两个相互独立的 grain Need，
   不建立"机构余额 → 产品余额"的 Need 依赖。
2. **查家底**：查询资产目录（fixture：A-003 `dm_ln_loan_month_product` 已存在同口径表）。
   - 命中且三阶段证据完整 → 预期决策 `reuse-as-is`；
   - 若只拿到目录记录、缺三阶段证据 → 预期 `cannot-determine` 并建立人工介入任务（不得仅凭物理表存在判定复用）。
3. **反向规划**：机构粒度余额应从共同上游 DWM（A-002）GROUP BY 月份、机构 聚合得到，
   不得从产品粒度 DM 再加工，也不得新建 DM → DM 依赖。
4. **三阶段设计**：对新建/扩展模型依次产出 conceptual → logical → physical，任一阶段未确认不得进入下一阶段。
5. **可加性**：机构余额广播到产品粒度展示时标记 `do-not-sum-across-product`（禁止沿产品维度求和）。

## 预期产物

- 待确认模型 Markdown（含两粒度字段清单、聚合口径、上游血缘）
- 物理确认后：PostgreSQL DDL（含 `COMMENT ON TABLE/COLUMN`）

## 判定要点（通过标准）

- [ ] 两个 grain Need 独立建立，无兄弟依赖边
- [ ] 共享来源使用 shared_source_id，而非语义依赖
- [ ] 资产决策不虚构；缺证据时进入人工介入而非 create-new
- [ ] 反向链 DM → DWM → DWD 完整且每跳命中矩阵规则（MD-001 / MD-002）
- [ ] DDL 仅在物理确认后生成
